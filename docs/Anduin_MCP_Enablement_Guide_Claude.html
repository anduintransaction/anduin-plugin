Anduin for Claude · Organization setup

Making Anduin available in your Claude organization

A short guide for your Claude organization admin. It walks through adding the Anduin plugin to your organization so your whole team can connect Claude to Anduin — no coding required beyond copying one file into place.

How this works, in plain terms. Claude lets an organization offer an approved set of plugins to its members through its own private "plugin marketplace." The setup is a one-time job: create a small private code repository your IT team controls, add a single entry that points to Anduin's plugin, and connect it inside Claude. You never copy or host Anduin's software — the entry simply points to it.

This is Claude's own standard, recommended way to distribute plugins — it follows Anthropic's official guidance, not anything Anduin-specific. So the same marketplace you set up here will manage every plugin you roll out in future, not just Anduin.

Good to know: a Claude organization marketplace only accepts your own private repository — you can't point it straight at Anduin's public one. That's expected; the entry inside your repository does the pointing for you. If your organization has no GitHub at all, skip to Installing without GitHub below — you upload a file instead.

Before you begin

  • You're an Owner (or Primary Owner) of your Claude Team or Enterprise organization.
  • Cowork and Skills are turned on for your organization.
  • Someone on your side can create a private GitHub repository and install the Claude GitHub App on it. If that isn't you, pass this guide to whoever manages your GitHub — the steps are quick. No GitHub? Use Installing without GitHub instead.
  • You know your Anduin region — US or EU. Your organization's Anduin account lives in one of the two, and you'll pick the matching entry in Step 2. If you're not sure, ask your Anduin contact before you start.

Set it up

  1. Step 1 — Create a private repository. In your company's GitHub, create a new private repository — for example, your-company/claude-plugins. You'll reuse this same repository for any Claude plugins you approve later, so give it a general name.
  2. Step 2 — Add one file listing the Anduin plugin for your region. In that repository, create a file at this exact location: .claude-plugin/marketplace.json. Copy one of the two blocks below — the one for your Anduin region — and change only the names in quotes to your organization's (the your-company… and Your Company parts). Leave the plugins section exactly as written — that's what points Claude to Anduin.

    If your Anduin region is US, copy this:

    {
  "name": "your-company-plugins",
  "description": "Claude plugins approved for use at Your Company",
  "owner": { "name": "Your Company IT" },
  "plugins": [
    {
      "name": "anduin",
      "description": "Anduin data rooms and fund subscriptions (US)",
      "source": {
        "source": "git-subdir",
        "url": "https://github.com/anduintransaction/anduin-plugin.git",
        "path": "plugins/anduin",
        "ref": "v0.10.0"
      }
    }
  ]
}

    If your Anduin region is EU, copy this:

    {
  "name": "your-company-plugins",
  "description": "Claude plugins approved for use at Your Company",
  "owner": { "name": "Your Company IT" },
  "plugins": [
    {
      "name": "anduin",
      "description": "Anduin data rooms and fund subscriptions (EU)",
      "source": {
        "source": "git-subdir",
        "url": "https://github.com/anduintransaction/anduin-plugin.git",
        "path": "plugins/anduin",
        "ref": "v0.10.0-eu"
      }
    }
  ]
}

    The two blocks differ only in the highlighted ref line — the Anduin release to install; the EU release ends in -eu — and the description. Use one Anduin entry only — the two regional builds can't be installed side by side. Keep names lowercase-with-hyphens.

  3. Step 3 — Connect the repository to Claude. In claude.ai, open Organization settings → Plugins & skills, click Add → Sync from GitHub, and enter your repository as owner/repo (for example, your-company/claude-plugins). If it doesn't appear, install the Claude GitHub App on that repository and try again. Claude runs a first sync automatically — allow up to 30 minutes.
  4. Step 4 — Try it yourself first. Set the plugin to Available to install for now (nobody receives it automatically), install it yourself, and ask Claude: "List my Anduin data rooms" (or "List my funds"). Claude will ask you to sign in to Anduin — use your normal Anduin account. If you see your own rooms or funds, the setup is correct. If not, see "If you get stuck" below before going further.
  5. Step 5 — Choose who gets it. On the Inventory tab, open the menu on the Anduin row, choose Default access, and set how the plugin is offered to your members: Installed by default, Available to install, Required, or Not available (which hides it). With the first or third, Anduin appears for your team automatically; with Available to install, they add it from Customize → Plugins (the Discover tab) — in chat, on Claude Desktop, or in Cowork — with no GitHub access needed.

That's it — the Anduin plugin is now available across your Claude organization.

What your team will see. A single connection named Anduin. The first time someone uses it, Claude asks them to sign in with their usual Anduin account; from then on, each person only ever sees what their own Anduin account already allows. Members never choose a region — you did that for them when you picked the entry (or the ZIP) for your region.

If someone already installed Anduin on their own. Ask them to remove that copy before using the one from your organization. Two Anduin plugins on the same account conflict, and only one of them will connect.

Installing without GitHub

If your organization can't create a GitHub repository or install the Claude GitHub App, an Owner can upload the Anduin plugin as a ZIP file instead. Your team gets exactly the same plugin. The one difference is that a ZIP doesn't update on its own: when Anduin publishes a new release, you upload the new file yourself (see Updating a ZIP install below). This is Anthropic's documented Upload a plugin route; the same Before-you-begin points apply, except for the GitHub one.

  1. Step 1 — Download the ZIP for your region. Both files are attached to Anduin's public release page, and downloading them needs no GitHub account. Take one file — the one for your Anduin region — and don't unzip it. If you prefer, ask your Anduin contact to send it to you.
    Your Anduin regionDownload
    USanduin-us-0.10.0.zip
    EUanduin-eu-0.10.0.zip
  2. Step 2 — Upload it to your organization. In claude.ai, open Organization settings → Plugins & skills and click Add → Upload a plugin. For a first upload, Upload to a new marketplace is already selected — give the marketplace a name (for example your-company-plugins); later uploads can go into that existing marketplace. Drop the ZIP into the upload area and click Upload. The file must be a .zip under 200 MB; Anduin's is well under 1 MB.
  3. Step 3 — Try it, then choose who gets it. The plugin now appears on the Inventory tab. Continue with Step 4 and Step 5 of "Set it up" above: install it yourself, ask Claude "List my Anduin data rooms", then set Default access for your members.

Updating a ZIP install. When Anduin announces a release, download the new ZIP for your region from the releases page, open the Anduin plugin from the Inventory tab, and choose Upload new version. The new file replaces the previous version under the same name, and members get it in their next Claude session. The plugin's Version history lets you compare versions or revert to an earlier one.

For a single person instead of the whole organization. If your organization allows user-created skills, anyone can upload the same ZIP to their own account from Customize → Plugins → Add → Upload plugin. In the Claude Code terminal, claude --plugin-dir ./anduin-us-0.10.0.zip (or the EU file) loads it for that session only.

Keeping it up to date

The plugin itself changes rarely. New Anduin tools and fixes are delivered by Anduin's servers and reach your team without any update; a plugin release mostly refines the guidance Claude follows. Anduin's announcement will say when an update matters for you.

If you installed with a ZIP, see Updating a ZIP install above. If you connected a repository, Anduin's announcement gives you the new ref line for your region (also listed on the releases page). Claude only re-syncs your marketplace when your repository changes, so:

  1. In your marketplace.json, change only the Anduin entry's ref line to the new tag, exactly as given (keep the -eu ending if you're on EU).
  2. Commit the change through a pull request and merge it.
  3. Open Organization settings → Plugins & skills → Marketplaces. If you've turned on Sync automatically, the merge may already have synced; otherwise click Re-sync on your marketplace.
  4. Check that the plugin shows the new version.

Members get the new version in their next Claude session. To go back, restore the previous tag the same way. Keep your other plugin entries, marketplace name and owner as they are, and check the file is still valid JSON before committing.

If you get stuck

  • Claude can't find your repository: make sure it's private and that the Claude GitHub App is installed on it — public repositories aren't accepted at this step.
  • Sign-in fails, or your funds and rooms are missing: first confirm your Anduin region with your Anduin contact and compare it with the ref line in your file (a tag ending in -eu is EU; otherwise US). If they don't match, change only that ref line to the value for your region (keep everything else in the file), commit, and click Re-sync on your marketplace; members should start a new Claude session and sign in to Anduin again. If they do match, check that the marketplace sync succeeded and that the member doesn't also have an older personal copy of the plugin installed; then check that they can sign in to Anduin itself and have access to the fund or room.
  • Plugins disappeared after an update: a failed sync can temporarily remove plugins for your members. Check that the file is valid JSON and the ref matches a release tag exactly, commit the fix, and click Re-sync again. Then confirm the plugin is still offered to your members the way you chose in Step 5.
  • Anduin is installed but Claude has no Anduin tools: check that the plugin is enabled and the Anduin connection shows as connected; reconnect it and approve the access it requests. If your organization limits which connectors members may use, an Owner must also allow the Anduin connection under Organization settings → Connectors — making a plugin available doesn't add its connector by itself. If it still has no tools, contact Anduin — the cause may be on the server side.
  • A chart or table doesn't appear: ask Claude for the result as text or a table instead.
  • No GitHub at all? Upload the plugin as a file instead — see Installing without GitHub.

Access is always user-scoped: making the plugin available doesn't grant Anduin anything on its own. Each person signs in individually, and Claude only ever reaches what that user's existing Anduin permissions allow.
